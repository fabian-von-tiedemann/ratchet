# D-2026-11-16-scope: what 0.3 takes in and what it leaves out

- Date: 2026-11-16
- Decided by: Ratchet's maintainer
- Kind: decision (D)

Names are left out of this file. Where the original names the external tester, a model or a reviewer, the name is replaced by a word in square brackets. Nothing else in the original is changed.

## Question

Original, in Swedish:

> Fem val till dig. Mitt råd är ja på alla fem.
>
> 1. **Rätta motsägelserna och låt Ratchet följa sina egna regler ([testarens] F1 och F5).** Kopian ska vara ordagrann rad för rad. Ett projekt får välja vilka rader det tar med, men inte skriva om dem. Ordlisteregeln och dess kontroll ska säga samma sak. Ratchet får en egen kort ordlista. Repot får egen AGENTS.md, ett första beslut om vad versionen medvetet lämnar ute och en överlämningsfil i repot.
> 2. **Ratchet levererar en fungerande kontroll (F2).** Reglerna samlas i `ratchet.yaml`, och tabellerna genereras därifrån. Kontrollen av att en kopia inte har glidit isär körs i CI. Den ska vara grön på en orörd kopia och röd på en testkopia med en ändrad rad. [En modell] skrev att Ratchet inte levererar några skript, och det ändras till att Ratchet levererar en referenskontroll. Jag skriver den i Python utan beroenden.
> 3. **Grenskyddet gäller också dig som administratör (F3).** Du mergar via PR, men utan krav på godkännande, så du blockerar inte dig själv. CODEOWNERS väntar tills agenterna har en egen GitHub-identitet. Annars ser en agents PR ut som din, precis som [testaren] påpekar.
> 4. **Kärnan fryses i 0.2 (F4).** `CONTROL-ROOM.md` och `SELF-IMPROVEMENT.md` följer med men märks som *experimental*. De står utanför kärnan och räknas inte i andelen regler som bara är text. Den andelen anges vid varje version och ska sjunka.
> 5. **Beslutsbokstäverna blir engelska.** Uppdelningen U/F/E/O behålls, och den värderar [testaren] högt. Bokstäverna blir D/P/O/Q (Decision, Proposal, Observation, Question), så att de går att förstå utan svenska.

Translation into English:

> Five choices for you. My advice is yes to all five.
>
> 1. **Fix the contradictions and let Ratchet follow its own rules ([the tester's] F1 and F5).** The copy is to be verbatim, row by row. A project may choose which rows it takes, but not rewrite them. The glossary rule and its check are to say the same thing. Ratchet gets a short glossary of its own. The repo gets its own AGENTS.md, a first decision on what the version deliberately leaves out, and a handover file in the repo.
> 2. **Ratchet ships a working check (F2).** The rules are collected in `ratchet.yaml`, and the tables are generated from it. The check that a copy has not drifted runs in CI. It is to be green on an untouched copy and red on a test copy with one changed row. [A model] wrote that Ratchet ships no scripts, and that changes to Ratchet shipping a reference check. I will write it in Python with no dependencies.
> 3. **Branch protection applies to you as administrator too (F3).** You merge through a PR, but with no approval required, so you do not block yourself. CODEOWNERS waits until the agents have a GitHub identity of their own. Otherwise an agent's PR looks like yours, just as [the tester] points out.
> 4. **The core is frozen in 0.2 (F4).** `CONTROL-ROOM.md` and `SELF-IMPROVEMENT.md` come along but are marked *experimental*. They stand outside the core and are not counted in the share of rules that are text only. That share is stated with every version and is to fall.
> 5. **The decision letters become English.** The split U/F/E/O stays, and [the tester] values it highly. The letters become D/P/O/Q (Decision, Proposal, Observation, Question), so that they can be understood without Swedish.

## Answer

Original, in Swedish:

> ja, kolla med [en modell] och bygg 0.3 som ytterligare. vassare version om det finns input som är värdefull

Translation into English:

> yes, check with [a model] and build 0.3 as a further. sharper version if there is input that is valuable

Translator's note: the full stop in the middle of the sentence is in the original.

## What follows

- **The version numbers moved by one.** The tag `v0.2` was already published, so what the question calls 0.2 is released as 0.3. See [D-2026-11-16-renumber](D-2026-11-16-renumber.md). What the answer calls 0.3 was planned as 0.4 and is not released: see [D-2026-11-16-register-only](D-2026-11-16-register-only.md).
- **The data file is `ratchet.json`, not `ratchet.yaml`.** Python's standard library reads JSON and does not read YAML, and the check was to have no dependencies. This is a proposal (P) until this PR is merged.
- **Point 3 was changed the same day.** An account of their own for the agents was decided, so code ownership came in. The protection is to require the code owner's approval and exempt administrators. Creating the account and setting the protection remain, and the handover in the root of the repo lists the steps. See [D-2026-11-16-code-owner](D-2026-11-16-code-owner.md).
- **The share of rules that are text only fell from 21 to 19 of 35.** Two rules became checks when code ownership came in, and one of the named checks now ships with Ratchet.

What 0.3 deliberately leaves out:

- **Checks for the other rules.** One rule has a reference check. For every other rule that names a check, the project still builds it.
- **New rules.** The core is frozen. Paying down the rules that are text only comes first.
- **A rule lifecycle.** Waivers, deprecated rules and stricter versioning are open questions.
- **Examples and other agent tools.** Filled-in examples, and equivalents for tools that do not read the same files, are open questions.
