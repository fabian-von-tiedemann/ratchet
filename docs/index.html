Ratchet

Agile was written for a team of people. Ratchet is for one person with a team of agents, who work fast, forget everything between sessions and say "done" with confidence.

We value:

  • Checks that catch mistakes over instructions that warn about them
  • Written decisions over remembered conversations
  • Shown results over reported success
  • Independent review over self-review

That is, while there is value in the items on the right, we value the items on the left more. The right is faster. It works while the agent remembers, obeys and judges itself well. The left is for when it doesn't.

How it works

  1. A rule describes a check that you build, or says “text only” and why it stays an instruction. Copied rules keep their wording, and the register check that Ratchet ships compares them with the version you state. “Decisions belong to the owner” is text only: a check cannot tell a fact from a decision. The rules
  2. Your repo keeps a register. One file lists every rule in force, the ones you copy and your own, and records which checks you have built. Ratchet ships only a few reference checks itself. Ratchet's own register
  3. It turns one way. When an agent errs, you add a check that fails on it. The loop

Ratchet today: the core has 19 rules. 13 describe a check and 6 are text only. Ratchet ships a reference check for 1 of the 13, and you build the others.

Start here

In the root of your git repo:

  1. Fetch Ratchet. 
    git clone --branch v0.12 https://github.com/fabian-von-tiedemann/ratchet .ratchet
  2. See what it would write. This writes nothing. 
    python3 .ratchet/checks/init.py --check
  3. Write it. 
    python3 .ratchet/checks/init.py
  • A new repo: init.py writes AGENTS.md, your register and a workflow that checks it on every pull request.
  • A repo with AGENTS.md, CLAUDE.md, GEMINI.md, .github/copilot-instructions.md or .claude/CLAUDE.md: init.py runs in adopt mode, never changes that file, and with --adopt writes a register that points at your wording. Rules in another form, such as .cursor/rules, get the new repo's files, so take inventory first.

You turn on branch protection on your host, so that the check is required. init.py never overwrites a file. What to do next
