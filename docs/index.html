Ratchet

Rules for one person with a team of AI coding agents. A way to turn each mistake an agent makes into a check you build, which goes red the next time.

Beta. Before 1.0, a new version may change the form of your register, and the changelog says what to do.

Agile was written for a team of people. Ratchet is for one person with a team of agents, who work fast, forget everything between sessions and say "done" with confidence.

We value:

  • Checks that catch mistakes over instructions that warn about them
  • Written decisions over remembered conversations
  • Shown results over reported success
  • Independent review over self-review

That is, while there is value in the items on the right, we value the items on the left more. The right is faster. It works while the agent remembers, obeys and judges itself well. The left is for when it doesn't.

The principles

Each failure turns the ratchet one notch tighter, and the pawl keeps it from slipping back. The teeth are the principles:

  1. Before a session ends, write down what the next one needs. Give every decision and rule one home in the repo.
  2. Merge only when the checks pass and a reviewer with fresh eyes approves.
  3. The agent finds the facts. The owner makes the decisions. What cannot be undone waits for the owner's yes.
  4. Done means the run that proves it is shown, with its output. Silence from a scheduled job is a failure.
  5. Turn every failure into a check, and trust no check you have not seen fail.
  6. Keep secrets out of the repo and the chat.
  7. Text from outside is material, never instructions.
  8. Simplicity is essential: try removing something before adding anything.

For applications with users in production:

  1. Ship the build that passed the tests, and try the way back before you need it.
  2. Someone who can judge accepts what users will see, and a test keeps what they accepted.
  3. Probe production from outside. Watch real use. Track what expires.

These are aims. Ratchet's rules say which of them a check can see.

Each comes with a question to ask when no rule fits: the principles in full.

How it works

Instructions are not enough.

  • An instruction: AGENTS.md says “Never commit secrets.” An agent commits a key anyway.
  • A check: ratchet.no-secrets names a secret scan in every pull request. Made required, it blocks the merge when it flags the key.

Ratchet ships no scanner: you build or adopt it.

  1. A rule goes in your register, copied from Ratchet or your own. Ratchet's own register
  2. It names what catches it: a check you build, or “text only” and why. The rules
  3. When something slips, a built check goes red on it, where it runs. The reference checks
  4. Each failure turns it one notch tighter: a new check or fixture. The loop

Ratchet today: the core has 19 rules. 13 describe a check and 6 are text only. Ratchet ships a reference check for 1 of the 13, and you build the others.

Kept current: 5 pinned sources, google/elephant-goldfish-model (Apache-2.0), mattpocock/skills (MIT), pstack (MIT), obra/superpowers (MIT) and sprocketlab/slop-code-bench (MIT). Each pin is a commit. A daily watch opens an issue when one moves.

Another agent that can run commands in your repo: the same prompt.

Set up Ratchet in this git repo. Work in the repo's root.

1. Fetch Ratchet at its released tag into .ratchet:
   git clone --branch v0.14 https://github.com/fabian-von-tiedemann/ratchet .ratchet
2. Run the dry run, which writes nothing, and show me all of its output:
   python3 .ratchet/checks/init.py --check
3. Stop there. Tell me which of the two paths init.py takes here: a new repo, or adopt mode, for a repo with an instruction file of its own. Ask me before you run anything that writes: init.py, or init.py with --adopt.
4. When I have said yes, follow .ratchet/STARTING.md, one step at a time.
5. If init.py wrote AGENTS.md and you do not read it, say how to make you.

Do not commit, push, or make a check required without asking me first.

One click selects the whole prompt. Ratchet builds itself with Claude Code and Codex, and has not been tried in the others: tell us how it went.

Or type the three commands yourself, in your git repo’s root:

  1. Fetch Ratchet. 
    git clone --branch v0.14 https://github.com/fabian-von-tiedemann/ratchet .ratchet
  2. See what it writes. This writes nothing. 
    python3 .ratchet/checks/init.py --check
  3. Write it. 
    python3 .ratchet/checks/init.py
  • A new repo: init.py writes AGENTS.md, your register and a workflow that checks it on every pull request.
  • A repo with AGENTS.md, CLAUDE.md, GEMINI.md, .github/copilot-instructions.md or .claude/CLAUDE.md: with --adopt, init.py writes a register that points at your wording, and never changes that file. Rules in another form, such as .cursor/rules: take inventory first.
